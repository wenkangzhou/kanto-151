# 跟着动画相遇

应用调整的是普通奖励的相遇／解锁路线，图鉴仍保留 #001–#151 编号与编号排序。不会把宝可梦重新编号，也不会把已有收藏变回未发现。

## 编排原则

这是面向孩子的无印关都篇主要故事路线，不是逐镜头首次露面清单。原路线六章共 30 位普通伙伴，新路线六段共 70 位普通伙伴，按故事的先后顺序逐个相遇；同集内部顺序是产品编排。它不读取孩子实际看到了第几集，也不按观看进度自动限制奖励。

梦境、电视、图鉴画面、回忆等短暂出现不优先于角色自己的主要故事。例如妙蛙种子、小火龙、杰尼龟分别安排在 EP010、EP011、EP012 附近；皮卡丘作为新家庭的第一位伙伴。原始参考采用 EP 编号，不保证与各视频平台的集数完全一致。

| 路段 | 故事范围 | 普通伙伴数 |
| --- | --- | --- |
| 和皮卡丘出发 | EP001–004：初次出发、火箭队、森林 | 11 |
| 小刚和小霞的伙伴 | EP005–009：道馆、月见山、训练家 | 10 |
| 三位新的好朋友 | EP010–016：隐藏村庄、小火龙、杰尼龟、灯塔、大船 | 6 |
| 海边与神秘的相遇 | EP017–029：海岛、幽灵、超能力、城市 | 19 |
| 一路上的新模样 | EP030–045：发电厂、地鼠、旅行、伊布、胖丁 | 16 |
| 向着石英大会出发 | EP046–083：古代伙伴与大会之前的相遇 | 8 |

EP035 的迷你龙和 EP038 的多边兽在一些发行版本中缺席；特别篇中的迷唇姐和拉普拉斯也不强行套用普通集数。四位留在六段之后，按本地数据中的固定顺序补齐。进化形态仍遵循前置形态＋进化券；传说门槛与梦幻规则保留，并不声称全部 151 只严格遵循动画出场时间。

## 一份奖励怎样选择伙伴

从当前最早未完成的路段中，取第一只尚未收集的普通伙伴。已收集的小火龙、杰尼龟等自动跳过，不重复发放。只有真正轮到的下一只显示“可遇见”。同一家庭的兑换保持数据库行锁和幂等保障；未使用的旧奖励码按新路线兑换，已使用的码仍返回当时的结果。

## 数据与维护

- `src/data/anime-route.json`：74 个普通形态的故事锚点、例外和来源，运行时本地读取。
- `src/data/chapters.json`：六段路线。
- `src/data/chapters-game-v1.json`：旧章节，仅供历史庆祝展示。
- `scripts/generate-sql-rules.ts`：将当前规则写入 `003` 的生成区域；后续再次更改已发布规则，应新增迁移，不重跑旧迁移。
- `scripts/sync-pokemon.py`：更新宝可梦元数据时保留人工编排的章节。

## 上线

已经执行过 `001` 和 `002`：在 Supabase SQL Editor 完整执行一次 `supabase/migrations/202609090003_anime_route.sql`，再部署新版应用。新安装按 `001 → 002 → 003` 执行。不执行清空、重建家庭或重新绑定设备。

升级保留收藏、券、奖励码、相遇结果。章节指针会重新计算，旧进度数字可能回到新路线较早的一站，这是补齐此前尚未收集的动画伙伴。旧相遇的 `route_version` 为 `game-v1`，新相遇为 `anime-v1`，历史章节庆祝不会被误改成新故事。
