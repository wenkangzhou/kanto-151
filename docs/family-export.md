# 家庭数据导出（版本 1）

入口：家长中心 → 家庭概览 → 保存家庭数据。必须有有效设备会话及未过期的家长解锁；演示模式禁用。每台设备每 5 分钟最多请求 5 次。

## 上线前

先按顺序完成 001—009，再在数据库执行 `supabase/migrations/202610220010_family_export.sql`，然后部署应用。本次只准备了迁移文件，没有执行生产迁移。新增函数只读数据，撤销 PUBLIC、anon、authenticated 的执行权限，仅服务端角色可调用；API 从已验证的会话取孩子 ID，不接受请求传入的归属。

## 文件内容

UTF-8 JSON 包含版本、导出时间、各部分记录数及 SHA-256 完整性校验。单个 SQL 语句在同一数据库快照中汇总全部记录，不经过默认 1,000 行的列表分页。

包含家庭和孩子资料、所有奖励码（含已兑换、撤销）、库存、相遇（含未开球）、收藏、主线与传说进度、小队、招式预设、完整已保存学习状态、使用时间设置以及无凭据的设备资料。

不包含家长 PIN 哈希、设备 token 哈希、配对码、服务端密钥、限流记录，也不包含尚留在其他设备本机的学习输入日志。设备语言、声音等本机偏好不在导出范围。文件包含奖励码和成长理由，应保存在家长自己的安全位置，不对外分享。

## 文件检查

```sh
node --import tsx scripts/backup/verify.ts /absolute/path/kanto-family-2026-10-22.json
```

校验允许重新排版 JSON，但任何内容修改、遗漏或记录数变化都会被检测。校验是损坏检测，不是数字签名，不能证明文件来源可信。

## 恢复边界

目前没有应用内导入入口，也没有生产数据库一键覆盖脚本。导出不替代数据库平台备份。

tests/family-export.test.ts 在两个全新的本地 PGlite 数据库中完成导出和业务数据重建：1006 张奖励码、相遇、库存、收藏及学习状态均在重建后重新导出并逐字段一致。重建使用新凭据，不复用旧设备登录能力。此测试不是生产恢复演练，尚未覆盖真实大数据量、并发写入、实体 iPad 下载保存或平台级灾难恢复。

真实恢复前应先校验文件，并在隔离数据库验证所有关联、重建新家长凭据及设备配对，确认无误后再单独安排生产恢复；不应直接导入现有家庭数据库。
