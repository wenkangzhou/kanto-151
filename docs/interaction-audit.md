# 全局交互检查（2026-09-18）

本轮以本地演示模式检查孩子和家长的主要操作链路，结合组件、路由与自动测试复核。没有修改真实家庭数据。浏览器验证使用桌面内置浏览器；不等同于真实 iPad Safari 验证。

## 已修复

- 背包的待开精灵球直接打开对应的已保存相遇，不再回奖励码输入页。
- 首页有待查看奖励时，主入口直接继续该奖励，合并原来的重复入口。
- 兑换、使用奖励券、开启最终相遇后立即同步收藏和背包，避免动画未结束就返回时看不到已保存结果。
- 背包点击某类券后直接进入该类券的流程。只有一张时自动选定，多张时保留选择，消耗前仍需确认。
- 用券步骤切换后再定位和聚焦到新内容，避免旧布局滚动位置让下一步落在屏幕外。
- 背包进入伙伴详情后返回背包；未发现伙伴的底部返回入口也遵循来源。
- 家长从进化/传说奖励表单进入记录再返回时，恢复原来的草稿入口，保留类型、理由和生成结果。
- 家长奖励说明随捕捉、进化、传说类型变化，不再统一描述为捕捉。

## 验证记录

| 区域 | 验证方式和结果 |
| --- | --- |
| 首页与开球 | 浏览器兑换演示码，动画前离开；首页直接链接同一 receipt，背包也指向同一结果；重试同一码仍返回原 receipt |
| 进化 | 浏览器完成背包 → 自动选券 → 选小火龙 → 最终确认 → 火恐龙结果 → 详情 → 返回 → 替换原队员，收藏与小队更新正确 |
| 传说券 | 浏览器验证单券直接进入符合门槛的候选；不符合条件的超梦未列为可选择对象 |
| 小队与对战 | 浏览器确认进化后的队员更新；从小队进入对战，第一次点选、第二次点选上场，速度顺序与一对一提示正常 |
| 家长端 | 浏览器验证演示 PIN、指定奖励类型、填写理由、记录页、返回原草稿；提示文字对应类型 |
| 图鉴与详情 | 代码复核筛选/排序/位置保存、已收集伙伴切换、安全返回来源；导航测试覆盖背包与非法来源 |
| 成长足迹 | 代码复核详情链接带 history 来源，返回入口由统一来源映射生成 |
| 重试和空状态 | 代码复核用券提交互斥、幂等重试、无可用目标提示；纯逻辑测试覆盖零张、一张、多张、混合类型券 |

## 保留与后续观察

- 使用奖励券和满队换伙伴保留最终确认，避免误用道具或换错队员。
- 本轮没有增加页面、导航项或额外确认弹窗。
- 首页地图的所选章节、背包和成长足迹的详情返回滚动位置，尚未像图鉴/小队一样专门记忆，可作为下一轮连续性优化。
- 真机仍需检查 iPad 横竖屏、触摸拖动、Safari 音频首次播放，以及家长手机软键盘遮挡；本轮未宣称这些已经验证。
- 不通过演示验证推断真实服务的断网、多设备并发、凭据恢复行为。相关数据规则由现有自动测试覆盖，但生产连接流程未操作。
